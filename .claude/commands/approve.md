오너 결재를 처리합니다. 입력: $ARGUMENTS

## 결재 수집
- **인자가 없으면 메신저에서 수집**:
  1. Discord: `python3 tools/discord.py inbox --after $(cat 결재함/.discord_last_id 2>/dev/null)` — 오너 메시지 중 `결재-NNN 승인|반려|보류` 형식만 결과로 나옵니다.
  2. Gmail: (a) `결재함/대기/` 문서의 `gmail_thread`를 조회(`get_thread`, PLAIN_TEXT)하고, (b) `search_threads`로 `from:오너 Gmail(.env의 OWNER_EMAIL) subject:결재회신 newer_than:14d`를 찾습니다 (메일의 선택 버튼이 만드는 회신). `오너 Gmail(.env의 OWNER_EMAIL)`이 보낸 메시지 중 상신 메일 자체가 아닌 것만 결재로 인정합니다.
     - 해석 형식: `결재-002 승인 B` / `002-B 003-A` (= 해당 안 승인) / `일괄 002-B 003-A 004-B` / `002 반려 사유` / `002 보류`
  - 회신이 없는 건은 "미결"로 표시하고 건드리지 않습니다.
- **인자가 있으면** `결재번호 결정(승인|반려|보류) [코멘트]`로 직접 처리합니다 (터미널 결재).

## 처리 절차
1. 해당 문서의 "오너 결재" 칸에 결정·코멘트·결재일·경로(Gmail/터미널)를 적고, frontmatter `상태`를 바꿉니다.
2. 승인·반려 문서는 `결재함/완료/`로 옮깁니다. 보류는 `대기`에 둡니다.
3. `00_CEO/의사결정로그.md` 표에 한 줄 추가합니다.
4. 승인된 건의 "승인 시 다음 행동"을 관련 팀의 `backlog.md` 맨 위에 추가합니다.
5. **승인 건은 바로 적용합니다**: "승인 시 다음 행동" 중 결재 범위 안에서 바로 할 수 있는 것은 담당 팀 서브에이전트로 착수시키고, 결과를 결재 문서 하단 "적용 내역"에 기록합니다. 결재 범위를 넘는 일(추가 비용·외부 공개)은 새 결재로 올립니다.
6. 처리 결과를 받은 채널로 알립니다: Discord는 결과 요약 파일을 `send`, Gmail은 같은 thread(`replyThreadId`)에 회신. 처리한 마지막 Discord 메시지 ID를 `결재함/.discord_last_id`에 저장합니다.
7. 오너 코멘트가 선택지와 다르면 코멘트를 우선하고, 해석이 모호하면 처리하지 말고 같은 thread로 확인 질문을 보냅니다.
8. 마지막에 처리 결과(처리됨 / 미결 / 확인 요청)를 표로 보여줍니다.
