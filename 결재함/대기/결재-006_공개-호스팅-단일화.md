# 결재-006: 공개 사이트 호스팅을 한 곳으로 정한다

## 결정할 것
결재-002(정적 공개)를 GitHub Pages와 Render 중 어디서 운영할지.

## 배경
GitHub Pages용 브랜치(gh-pages)와 Render용 설정(package.json·render.yaml)을 둘 다 준비했다. 두 곳을 같이 운영하면 홍보 링크가 갈리고, 수정할 때마다 두 곳을 확인해야 한다.

## 선택지
| | A안 GitHub Pages (권고) | B안 Render | C안 둘 다 |
|---|---|---|---|
| 비용 | 0원 | 0원(무료 플랜) | 0원 |
| 남은 작업 | 저장소 Settings → Pages에서 gh-pages 선택 1회 | Static Site로 다시 만들고 Publish dir=app | 둘 다 |
| 장점 | 이미 저장소에 있음, 푸시하면 자동 갱신 | 사용자 지정 도메인·서버 확장 쉬움 | 한쪽 장애 시 대체 |
| 리스크 | 서버 기능 없음(Notion 저장은 별도 Worker) | 무료 플랜은 첫 접속이 느릴 수 있음(Web Service일 때) | 링크 분산, 관리 2배 |

## CEO 권고
A안. 추가 계정 없이 푸시만으로 갱신되고, 서버가 필요한 Notion 저장은 이미 Cloudflare Worker로 분리돼 있다.

## 승인 시 다음 행동
- A: 오너가 Settings → Pages 설정 1회 → 개발팀이 공개 확인, 홍보 링크 확정. Render 서비스는 정지
- B: Render Static Site 재생성 안내, gh-pages 브랜치 삭제
